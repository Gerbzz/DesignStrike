# DesignStrike foundation and verification

## Provenance

- Official counterpart: [DesignCraft](https://getartcraft.com/apps/designcraft), with [public Rust source](https://github.com/storytold/designcraft).
- Exact source pin: `a930276fd7462f3d9abd2fbb38544c94c0c911c8` (2026-10-15). This repository begins from a new root snapshot so restricted upstream `docs/brand/` artwork is absent from public history.
- Software licence: MIT OR Apache-2.0. The upstream NOTICE and ASSETS.md retain third-party terms. The open-licensed inherited cat app icon has a separate explicit licence. The approved PWDS bitmap is copied unchanged under its owner's terms.

## Foundation

The complete DesignCraft workspace supplies a native egui editor, headless CLI, web host, page and spread document model, threaded stories, paragraph composer, parent pages, styles, swatches, text wrap, PDF and IDML paths. These are upstream source capabilities, not DesignStrike acceptance results. The app remains on a pre-alpha publication gate in upstream [docs/gaps.md](gaps.md).

DesignStrike changes the visible native window, welcome screen, About panel, and project links, while preserving `.designcraft` document and internal package names for compatibility. The old ArtCraft mark shape was drawn in code; that code and the separately licensed `docs/brand/` files were removed before the new public root was committed.

## Verification

[Hosted Ubuntu 24.04 run 38729864589](https://github.com/Gerbzz/DesignStrike/actions/runs/38729864589) passed against fix commit [`1d5172420b5fc97022ad9a5020eeb25292a33860`](https://github.com/Gerbzz/DesignStrike/commit/1d5172420b5fc97022ad9a5020eeb25292a33860). No local Rust compilation used the shared Windows build slot.

The test launched the actual desktop editor under Xvfb/software OpenGL. It captured the [welcome screen](images/designstrike-welcome-ubuntu24.png), [About panel](images/designstrike-about-ubuntu24.png), [editor](images/designstrike-editor-ubuntu24.png), and [edited fifth page](images/designstrike-edited-page-ubuntu24.png) after native frames rendered. The [machine-readable report](evidence/designstrike-verification.json) records five reopened pages, one parent page, 15 paragraph styles, five PNGs, five PDF pages, five rasterized PDF pages, selectable edited text in PDF, a five-page IDML export/reimport, and an unchanged native document hash. The hosted artifact also contains inspect JSON and process logs, with one-day retention.

All five exported PNG pages and all five rasterized PDF pages were visually inspected. They contain the expected cover, article spreads, color page, edited fifth page and folios; the adjacent-page purple strip is absent. Review the PNG exports for pages [1](images/designstrike-export-cover.png), [2](images/designstrike-export-page2.png), [3](images/designstrike-export-page3.png), [4](images/designstrike-export-page4.png), and [5](images/designstrike-export-page5.png), and the PDF renders for pages [1](evidence/designstrike-pdf-page1.png), [2](evidence/designstrike-pdf-page2.png), [3](evidence/designstrike-pdf-page3.png), [4](evidence/designstrike-pdf-page4.png), and [5](evidence/designstrike-pdf-page5.png). ### Windows hosted result

[Run 38746493794](https://github.com/Gerbzz/DesignStrike/actions/runs/38746493794) passed on a standard public `windows-2025` runner at code commit `b9567649e098ac27e5a63cd2aee1ec5e0e0c0153`. It built the complete native editor and CLI, passed the two targeted page deletion and facing-page bleed regression groups, created and reopened a five-page `.designcraft` document through the CLI, and then drove the actual Windows editor through its loopback control API. The editor created and saved the same five-page synthetic publication, and its `ui.screenshot` method captured the [About panel](images/designstrike-about-windows2025.png), [page-three editor](images/designstrike-editor-windows2025.png), and [edited fifth page](images/designstrike-edited-page-windows2025.png). I visually inspected all three current Windows captures; the selected page and text frame are visible. `desktop-status.json` in the run artifact records a live native process and nonzero Windows main-window handle.

A separate Windows CLI process reopened the native file and exported five page PNGs, a five-page PDF and IDML. The retained [verification report](evidence/designstrike-windows-verification.json) confirms one parent page, 15 paragraph styles, selectable edited PDF text, a successful five-page IDML reimport, and an unchanged native document hash during reopen/export. Windows used a pinned 310 KB pure-Python PDF inspector because Poppler was absent; it did **not** rasterize or visually inspect the Windows PDF pages. The GUI screenshots are from the running app's screenshot API, not an operating-system screen capture. Earlier Windows attempts exposed only test-harness assumptions about viewport width and Python's cp1252 default for UTF-8 CLI output; application code was unchanged. These are synthetic Windows source checks, not print or production acceptance.

### Primary-story text-wrap regression

[Red hosted run 38772114929](https://github.com/Gerbzz/DesignStrike/actions/runs/38772114929) compiled a focused end-to-end engine test at commit `45248dc4cc7593e93da83bf3c404acc70217bf8c` and failed the intended assertion: adding a full-page bounding-box wrap object left a short primary story on one page when it needed a second. [Fix commit `1c00f32339e51027b308c7433de583b5bef3caae`](https://github.com/Gerbzz/DesignStrike/commit/1c00f32339e51027b308c7433de583b5bef3caae) makes Smart Text Reflow compare the wrap exclusions used by the primary frames' composer after story, style, and frame checks. The deliberate frame-deletion guard remains in place. The test also checks that removing wrap removes an empty trailing page; the existing page-deletion regression now checks that wrap outside the primary frames does not recreate a deleted page.

[Green Ubuntu run 38772715516](https://github.com/Gerbzz/DesignStrike/actions/runs/38772715516) passed the focused wrap test, the existing page-deletion and facing-page bleed regressions, 566 engine library tests (one ignored), and 35 renderer library tests. It built the native editor and CLI, drove the actual editor, reopened the saved five-page document, and exported five PNG and five PDF pages. The report confirms selectable edited PDF text, five rasterized PDF pages, IDML export/reimport, and an unchanged native file hash. This verifies the synthetic case and workflow at that commit; representative publication layouts remain unvalidated.

[Windows run 38772715620](https://github.com/Gerbzz/DesignStrike/actions/runs/38772715620) also passed at the same fix commit: native editor and CLI build, existing deletion and bleed regressions, five-page native save/reopen, and five-page PNG/PDF and IDML export. The Windows PDF was inspected structurally for page count and selectable edited text, not rasterized or visually checked. The wrap regression itself ran in the Ubuntu workflow.
